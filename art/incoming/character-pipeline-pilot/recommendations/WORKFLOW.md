# Candidate workflow for a future owner-approved revision

1. **Keep the current approved foundation for the next motion-only trial.** Pin the existing body, texture, head, bind, palette hashes and wardrobe mask. Render the original capture in source space. Select takes with heel/sole evidence and clip ground speeds that match the controller’s intended range. Record the publisher, license, source window and checksums before taking an asset into the repository.
2. **Retarget into each rig’s measured rest space.** Preserve recorded heading changes that belong to the motion and extract steady ground translation into an explicit speed value. Bake the same normalized source for comparison at 30 Hz. Resolve pose and tangent continuity, wrist roll and finger shapes. Fit contact IK for plant intervals and verify residual heel/toe speed after applying translation. Review idle, walk, jog and sprint transitions as well as the loops. Source runs near jog speed need a faster sprint companion for the current controller.
3. **Use MPFB as a source for a separate anatomy trial.** Build from a body preset with morph values and versioned reference art. Fit the deform skeleton after morphing and keep the editable source with its helpers. Use a pinned joint semantic map for shared animation retargeting. Prove head/neck joints, hand rest pose and shoe ground placement before generating a wardrobe. Export the baked runtime shell and eyes with a texture and triangle budget, top-four normalized weights and per-root motion receipts. CharacterCreator’s joint offsets are relevant if the design later needs live body sliders. This pilot validates fixed baked proportions.
4. **Version fit by body shape and bind signature.** Retain approved patterns, UVs and materials, then fit the shell to the new template and interpolate body weights. Record a per-slot mask against the exact runtime body indices. Test unmasked and masked stills at the neckline, cuffs, waist and shoes. Run stress samples and overlay garment/body intersections before declaring an outfit usable. An existing skeleton name match is insufficient if inverse binds differ.
5. **Keep modular contracts at the authoring boundary.** Complexions can be texture/material presets with a consistent UV atlas. Identity morphs can reuse topology, but face shape, eye fit, head-swap seam and weights require review for every variant. A continuous MPFB skin avoids the pilot seam by construction. A future removable MPFB head requires an agreed ring and seam-conforming morph set. Hairstyle slots can keep a common attachment convention if scalp fit and hair weights are tested under each head and hood. NPCs can share motion capture libraries and rig semantics, with body-size-specific contact and root-speed receipts. Female and NPC production require new owner approval and validation of proportion endpoints, joint fit, clothes and hair.
6. **Keep comparative QA close to exports.** Store a pinned baseline, equal-scale front/side/rear view, 200 ms transition test, 30 Hz motion measurements, naked-eye topology review and device measurements. Preview a representative clip on a physical iPhone before treating runtime metrics as a mobile sign-off. Retain checks for topology, exported influence count, texture size, load errors, visible draw calls, frame time and loop transitions.

## Proposed documentation changes for owner review

- In the character pipeline, allow a verified commercial/redistributable mocap route and versioned bone maps. Add source capture checks, contact metrics, gait speed envelopes, head pitch, finger pose and motion transition gates.
- In the male protagonist handoff, keep the current body/rig contract for animation-only deliveries. Describe an approved rebind declaration for alternative foundations with explicit garment, face seam and joint compatibility metadata.
- In the reviewer workflow, add a browser A/B/C gate, matched day/night and phone framing, source/target loop evidence, and a distinction between authoring source and runtime weight budgets. A readable production checklist can allow equivalent validated rigs after owner approval.
- In player-controller documentation, describe how clip speeds and clamp ceilings constrain playable travel. If a future motion library introduces separate jog and sprint tiers, decide state transitions and cadence on the integration branch with Claude.
