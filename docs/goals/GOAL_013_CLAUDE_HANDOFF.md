## Gameplay APIs and error contract

Imports from `systems/RobberyCareer.ts`, `systems/Robbery.ts`. Error functions return `string | null` (undefined only when intentionally absent quote/target). Command functions in Career return **new GameState or an error string**; they do not partially commit failures. `startRobbery` returns `{state,error}`; `robberyInput`, `pauseRobbery`, `leaveRobbery` return state and reject stale/replayed commands by unchanged state. Internal mutating helpers (`initializeCareer`, `settleCareer`, tick, seizure) are not UI entry points.

| Function | UI behavior |
|---|---|
| `careerOpportunities(s, location)` | List authored targets, human-readable error and cooldown; no rewards/rolls generated by browsing |
| `offerTarget(s, targetId, victim?)` | Notice a local ordinary/liquor/named opportunity; no AP or free goods |
| `offerCareerLead(s, source, targetId)` | In-person trusted trio/Quanny lead; requires 3/9 real successes; grants existing access milestone, never XP |
| `inviteRobbery(s, member, jobId)` | Accepted persisted invitation; in-person, willing Set or earned Mega/trio/Quanny contact, 45 directional trust, existing cooperation/availability and equipment rules |
| `partnerError`, `careerStartError`, `robberyStartError` | Preview rank, AP, physical location, availability, preparation, equipped valid firearm, accepted roster and cooldown failures BEFORE spending |
| `startRobbery(s, jobId)` | 1 AP, player required prep and participant gloves/mask consumed ONCE, rolls/contents/roster persisted, cooldown and heat begin immediately |
| `robberyInput(s, sessionId, cursor, answer)` | Contextual operation choices; always pass current cursor |
| `takeLoot(s, sessionId, cursor, lootId, carrierId?)` | Real physical gain after capacity validation; participating Set members may carry loot in own slots; invited non-Set contacts carry own gear only |
| `tryDial(s, id, cursor, position)` | Optional HOME bonus, 0–100 integer, three untimed tries, near/far/open feedback; pressure per try; target and attempts persist |
| `pawnQuote(s, slotId)` | Stored retail estimate and current ONE-ratio offer, owner/quantity; null for noneligible items |
| `dispositionError(s, slotId, originalOwner?)`, `sellProperty(...)` | Real pawn sale OR exact-original-owner sell-back; actual item, presence, owner funds/capacity required; no sale twice |
| `payCrewClaim(s, claimId)` | In-person goods buyout payment; explicit due date, exact amount and paid ledger |
| `answerExtortion(s, demandId, pay)` | In-person personal demand; real provenance-preserving transfer or durable grievance |

Representative errors are plain presentation strings: “Need N more load capacity”, “Visit the Reservoir Pawn Shop with the item on you”, “Only its exact original owner…”, “Requires an accepted in-person invitation…”, “Neighborhood/target cooldown: day N; started day D by JOB”. Do not key logic on localized string text: derive disabled state from a non-null error and read structured cooldown/claim/quote fields for numbers.

## Session presentation

`activeRobbery.career` distinguishes new templates from pre-GOAL013 sessions. Never show the old colored-symbol puzzle for a career session.

- `cursor` is a monotonic command revision (including taking loot and optional dial input), NOT a three-beat limit. Replayed cursor cannot execute twice.
- All types start with `patient | rush | withdraw`. No firearm discharge input or automatic firearm use.
- Home: first room revealed, then `search` (up to three rooms) / `leave`. Display each revealed `goods[]` entry: immutable `id`, item, quantity, estimated retail `value` (total, not per unit), load from registry, `locked`, `takenBy`. Never award items/cash in React. Normal cash and ordinary loot need no lock. Exit is a coherent completion; extra searches/tries lower exit chance and add exposure.
- Strong-arm/liquor: `deescalate | press | leave`. Press adds pressure, leave gives item-only strong-arm/partial liquor proceeds. A civilian cash drop is always $25–75; high-value victim cash is separately bounded and debited.
- Commercial: `coordinate` is required to reveal the collection after approach, then finish/press/leave. Trained equipped partner changes actual outcome probability. A Law-19 or another physically carried, rank-valid equipped firearm qualifies; stronger valid equipment improves the chance. No dial.
- Optional lock: present touch buttons in increments of 10, try and feedback (within 10 opens). The API supports integer positions. It is an abstract, untimed game with no audio/precision/motion requirement or real-world bypass instructions. Optional locked valuables appear in only 12% of home visits.
- Pause/resume uses existing persistent session lifecycle. Hidden document or leaving City pauses; day change, arrest, hospitalization or physical departure abandons, removes unsettled selected loot, and retains spent AP/prep/cooldown. No timers or frame work added.

**Mobile review:** retain 44px targets, scroll within existing inspectors/playback, no controls beneath HUD/nav, reduced-motion behavior, readable value/load/crew-cut previews. Verify actor-specific carrier selection and disabled capacity errors. Add final tactile dial/loot presentation as desired without changing rule ownership.

A trusted, willing Set member can also occasionally share a local home lead while physically together (every ten-day opportunity window, 55 trust, three real successes, no live lead or local home lock). This grants no AP, cash, XP, participation or obligation; the lead expires in six days and still requires an actual equipped partner invitation.

## Money, loot, consequences

Central tuning: `ROBBERY_BALANCE` in `content/robberyCareer.ts`; physical capacity remains in `content/inventory.ts`. New item IDs: `phone` (1 load), `plain-chain` (1), `jewelry` (1), `high-chain` (1), `console` (5), `pc` (8), `art` (10). Existing smokes/booze/Pink Magic reused. Cash never takes inventory slots. Duffle has real load, no magic bonus.

Loot provenance: `stolen:<lootId>`. `robberyCareer.property[lootId]` stores original owner, acquisition event, job, item, quantity and seeded total retail value. Quotes prorate that total to the carried stack quantity, so splitting cannot multiply proceeds. Provenance survives split, transfer and safe storage. Owner recognizes the actual property identity, not generic item type. The canonical MEGA chain/Chains property is NEVER minted or substituted. Named stock draws from actual carried lots when present; otherwise a persistent finite four-unit stock/one-jewelry authored pool, without replenishment. Source loss is recorded; new stolen lot has zero cost/owed; preexisting receivables survive.

Pawn: 63% base retail, modest heat/standing adjustment bounded 55–70%, no second discount. Illegal weapons and Pink Magic excluded. Sell-back: 72% retail; owner pays real wallet cash, receives property only if it fits. Preview **guaranteed active personal beef +8 notoriety**. Conflict uses existing `worsening/seek` state, personal scope, and `requiresReconciliation` so autonomous cooling cannot erase it; existing actual reconciliation scenes remain valid. No faction war or guaranteed death.

Crew: one initial partner, 25% immediate cash paid once; selected retained goods create 25% base-pawn-value buyout due within five days, even if subsequently lost (disclosed before invitation). Pay in person; overdue claims create personal grievance, persist through removal/incapacity and reload. No hidden “free labor” or rerolled cuts. Companion Combat and equipped attack bonus affect exit chance; failure may arrest both or mark partners laying-low and unavailable for two days of recovery.

Heat: existing CriminalExposure at start, search and settlement, with repeats and Downtown premium. Visitors have per-day/place durable identities/memory. Witness memories use only actual people at the place. A local affiliated DIRECT witness can ask 10–20% of known/estimated recorded take on a later day, at most one demand per job and one in four credible rumors. Refusal is personal, not a faction toll.

Home cooldown key `home:<zone>`: attempt day D ⇒ next day D+5, all houses blocked in between. Independent of character, outcome, source, house, expiry, reload. Other targets use `place:<location>` (next day) or `victim:<id>` (seven days), with finite victim valuables.
